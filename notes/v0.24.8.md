A copy of three files is now three files, and the search can be typed
a file name.

The clipboard read the pasteboard the way most tools do, which is to
take the first thing on it and call that the copy. The pasteboard does
not work that way. Three files selected in Finder go on it as three
items, and Lodestar kept the first — so a card that looked like your
copy pasted a third of it, silently, at the moment you were relying on
it. Every item a copy carries is now kept, and every one of them goes
back, so three files arrive as three files. The card says what it is
holding — **3 files** — and reads by name, which is how you would look
for it. A copy past thirty two items is left alone entirely rather
than kept in part, because a card that pastes some of what you copied
looks exactly like one that worked.

That name is new as well. A single copied file used to reach the
history as a card reading "clip", because a file carries no text and
there was nothing to show for it. A file's address is text — a URL,
sitting on the board — so the card shows the path and the search finds
it.

Searching the strip took letters, digits and the space bar, and
nothing else. Which meant it could not be typed most of what a
clipboard actually holds: a file name, a flag, an identifier, a
command. Every key that types a character now extends the query —
hyphens, underscores, slashes, dots — through the same table `lode /`
has always used, so the two searches answer a keyboard the same way.

And the cards are addressable again while you type. Once the band is
open the letters belong to the query, so a chip reading "A" was naming
a key that no longer did that, and the fourth match could only be
reached by walking to it with the arrows. **`⌥letter` pastes that
card** now, `⌥⇧` pastes it as copied, `⌥⌘` opens its actions, and the
chips wear the `⌥` for exactly as long as it is true. Control stays
what it is everywhere else in Lodestar, the secondary click, rather
than meaning two things one mode apart.
