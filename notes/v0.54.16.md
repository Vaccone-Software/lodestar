Lodestar now lets go of far more memory when your Mac runs short. On a memory warning it used to release the editor's model, about 2.7 GB, and keep the 20 GB language model that tidies a draft, which waited out its five minute idle timer. That model now goes on a warning too, right away, or when the draft closes if you are dictating. The next draft loads it again, as it already did after any five minute gap. The model that hears you stays until memory is critical.

The editor's model also stops coming straight back. On one evening it was reloaded within fifteen seconds of five warnings out of seven, into the same shortage that had just sent it away. It now waits at least five minutes after a warning, and longer if the system still says memory is short, up to half an hour. Spelling and the rules keep working during that time, and the grammar check picks up the sentences that waited.

The memory MLX keeps for reuse now has a limit of 64 MB. It saves about a gigabyte while dictating, and in testing nothing got slower and the words heard did not change.

Finally, the log now records memory every five minutes and whenever the level changes: what Lodestar is using, how short the system says memory is, and the largest applications running. If your Mac freezes and has to be forced off, which leaves no report behind, this is the record of what was in memory at the time. It stays in the local log on your Mac, and nothing here sends it anywhere.
