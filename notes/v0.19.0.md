Nothing takes your focus, and nothing holds your keyboard.

Lodestar could hand a clicked link to itself. If `web.clicks.browser` ever
came to name Lodestar, every link you clicked went round in a circle: macOS
hands us the link because we hold the http role, we hand it on to the
browser on file, the browser on file is us — and each lap brings Lodestar to
the front. Measured on the machine it happened to, from its own event log:
4,855 opens of one address inside a single minute, eight milliseconds apart,
in bursts that ended only when Lodestar was quit. Your focus was being taken
about ninety times a second and given straight back to nobody.

The value got there through an identity check that could not fail closed.
Lodestar watches which browser answers for links so it can hand yours back
untouched, and it refused to write itself down by comparing the candidate
against its own bundle identifier — which is empty for a build run outside
an app bundle, the way the app is run while it is being worked on. Empty is
not equal to anything, so the refusal never fired, and one such run was
enough to leave the loop in a config file that every boot afterwards
inherited.

Three things stand there now where nothing did. The write refuses to record
Lodestar as your browser. The config, read at every boot, treats that value
as no browser at all and tells you so, which is a state links already
survive — they go to whatever else answers for the web, and Safari after
that. And the hand-off refuses it a third time, so a file edited by hand
cannot make the circle either. Behind all three sits a cap on how often one
link may be handed off at all: the guard for a cause nobody has thought of
yet. Three separate checks that should have caught this could not, and each
of them can now — including the boot check that had been reporting the
broken configuration as healthy every single morning.

Gestures no longer wait on a hung app, on the paths the last release missed.
0.18.0 took window moving off the keyboard and said why: while Lodestar is
talking to another application, every key on the machine is waiting, and an
application that has stopped answering takes a second to say so. It moved
the work that arrives one way and left the work that arrives another.
Restoring a breath went the second way — thirty-odd conversations with other
apps, all of them inside the keyboard — and so did pressing a hint,
entering select, jumping to the end of a scroll, and saving an image from
the clipboard card. All of them now decide instantly and act a beat later,
which is the only thing that was ever needed: whether to swallow your
keystroke is knowable without doing any of the work behind it.

Two of them come out better than they went in. Pressing escape the moment
after entering select now cancels the screen capture instead of paying for
it, and leaving scroll mode cancels a jump that has not happened yet.

What stays inside the keyboard stays there on purpose, and the reasons are
written down beside the code: a paste must not land after the key you type
next, and select's copy exists precisely so that the next thing you type
replaces what it selected.

The coach speaks only to someone who is there. It now stays quiet when the
screen is locked, when the display is asleep, when the session belongs to
another user, and when no key has been pressed by a hand in two minutes —
counted on Lodestar's own clock, because the system's idle timer is reset by
software-generated keys and therefore reports a present, attentive user most
confidently on a machine where nobody has been for hours. A suggestion is
also spent when it has been seen rather than when it was drawn, so a chip
the app takes back after a moment costs you nothing, and re-opening a parked
one from the menu costs nothing either. The chip stands for thirty seconds
now instead of twelve, one showing per suggestion, and never twice inside a
minute.

And nothing driven by an agent can answer for you. Double-tapping lode
writes a line into your config; lode ⌫ buries a suggestion for thirteen
weeks. Both now require a keystroke that no other program posted — judged by
the process that stamped the event rather than by the label on it, because
the label can be forged and the stamp cannot. What that can and cannot tell
apart is written down where it is decided: it knows whether another program
injected a key, never whether a finger did, and a keyboard remapper is
indistinguishable from a keyboard, as it must be.

The rest are small. A flash no longer leaves a suggestion that has left the
screen still answering to the gesture that accepts it. Uninstalling no
longer hands the browser role back to the app it is about to delete. And a
Lodestar panel can no longer find its way into the window model and be
treated as one of your windows.
