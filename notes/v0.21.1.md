The calendar prompt appears.

0.21.0's meetings could not actually ask for the calendar. The purpose
string was in place and the card said the right things, but the app is
signed with the hardened runtime, and the hardened runtime is a
whitelist: explaining an ask in the Info.plist is not the same as being
entitled to make it. macOS answered "denied" on your behalf, silently,
about a second and a half after you clicked Allow — no prompt, no
error, a feature that looked enabled and could never work. The signing
lane now declares the one entitlement the ask requires, and the prompt
appears.

Found by the first person who clicked the button, which is the correct
number of people. The staging previews could render every card of this
feature; only a signed, notarized build on a real machine could fail to
show a system dialog. That gap between what a preview can prove and
what a signature changes is now written into the release script beside
the fix.

Also: turning meetings off and on again shows the permission card
again. It used to show once per boot no matter what, so a second
attempt in the same session asked for trust invisibly.
