The click door presses what the accessibility tree could not name, and
spends its letters where typing cannot reach.

A web page is not made of buttons. It is made of divs that press, images
that open menus, rows that pick a channel, and the tree has no name for
any of them, so the door's list of roles walked past them all: in one
Brave window it named seventy-three pressables and missed ninety-one
more, in Slack it missed the channel list entire. Now anything small
enough to be a control rather than a card is asked the only question that
matters, which is whether it presses at all. Only the innermost press
counts, because the tree presses all the way up, and a chip on the card
wrapping the row wrapping the button would put one letter over a whole
region.

A chip is not free. It is a word the eye must find and the hand must
spell, and the door already owns a better address for most of a window:
the text painted on it. So while a harvest fits in single letters
everything wears one, which is the small window's whole experience, a
dialog's three buttons each on one keystroke. Past that the letters go
only to what paints no word — the presses the tree found by action alone,
and the input boxes whose text is yours to write. A Brave window that
drew seventy-three two-letter chips now draws ten single-letter ones, and
the sixty-five that carry a name are reached by typing the name.

The labels are three rows in one fixed order, read from the live layout
so a chip always names the key that types it: the home row, then the top
row, then the bottom. The hand never leaves home while a home key is
unspent, and past it reaching up beats reaching down, ten keys to seven,
on the row the fingers already travel for e, r, t, i, o and u. Twenty-six
letters mean twenty-six targets answer on one keystroke where nine made
every one of them two. The order never varies, because a chip that moved
rows between windows would be a fresh decision every time.
