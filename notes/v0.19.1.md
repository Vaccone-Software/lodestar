Restoring a breath puts the same window back every time.

A breath remembers the windows that were on screen when you saved it. Windows
die — you close a tab, an app restarts — so when one of a breath's members is
gone, Lodestar looks through that app's live windows for the one that best
answers the title it recorded, and takes that one instead. It then writes the
substitution down, so the breath quietly re-points at the window you actually
have.

Which window it picked was luck. The candidates arrived in the order a Swift
dictionary happened to hold them, which the language does not define and
which is reshuffled every time the app starts, and the code took the first
one that matched. With one window open there was nothing to get wrong. With
four Brave windows open, restoring the same breath twice could hand you a
different one each time — and because the substitution is saved, the wrong
answer stuck.

The matching was also looser than it looked. A title counted as a match if
either title contained the other, with no length requirement at all, so a
window titled with a single character matched almost anything and could take
a place in your layout from the window that belonged there.

Both are fixed. Titles are now ranked by a rule that is total — an exact
title beats an overlapping one beats a shared opening, a short fragment
carries no weight at all, and the ordering cannot be upset by however long
another application decides to make a window title. Anything the ranking
genuinely ties is settled the way every other window lookup in Lodestar has
always settled a tie: the one you were in most recently. The rule sits in the
core with tests on it, including the single-character case that started this.

Two smaller things. The table that keeps Lodestar from re-waking an app's
accessibility tree more than once every thirty seconds kept one entry for
every program you had ever switched to, for as long as the app was running;
it now keeps only the entries that can still answer anything. And the code
that carries a saved-state file forward when its format changes could not be
tested, despite a comment claiming otherwise — the version it was migrating
to was baked in rather than passed, so with only one format in existence
there was nothing to migrate. It is exercised properly now: several steps in
order, a gap in the middle that must not halt the chain, a file with no
version at all, and a file written by a newer Lodestar, which must be left
alone rather than dragged forward. That code runs for real exactly once, on
everybody's machine at the same time, and this is no longer the first time it
will have run.
