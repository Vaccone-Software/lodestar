The Secure Input notice in 0.54.9 never appeared, and this release makes it work. When an app holds Secure Input, macOS names that app truly only while it is in front. Once it goes to the back, macOS names whatever app came forward instead, so Lodestar always found the holder in front, took it for someone typing a password, and stayed quiet.

Lodestar now remembers the app that turned Secure Input on, at the moment it began, when that app is still the one in front, and keeps it until Secure Input ends. It looks twice a second so that moment is not missed. When the holder has stayed at the back for two seconds, the lode key appears, faded, beside a line naming it, and a click brings it forward. If Secure Input was already on when Lodestar started, or began behind a locked screen, nobody is named until it has been off once, since Lodestar cannot know who turned it on.

Underneath, the core of Lodestar is now built in Swift 6 mode, where a data race is a compile error rather than a rare crash. The log, the event log, the key tables, the control socket, the window model and the stores each keep what several threads share behind a lock of its own. Nothing you see changes. The tests around it were rebuilt too: every window they open stands on a display far from the real ones, and a test that leaves a setting changed fails by name.
