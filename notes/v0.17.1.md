A selection that runs down the page.

Select could only ever reach along the line it started on. You would type a
word, pick it, type the far end — and if the far end sat one line below, no
chip ever appeared for it. The cause was invisible, which is what made it
maddening: what select searches is a run, prose stitched back together from
the fragments a window actually draws, and that stitching is deliberately
careful, because a run that merged two unrelated columns would promise a
selection it could not keep. On a busy page that leaves most runs a line or
two long — the page measured for this release turned 85 recognized lines
into 58 runs, 44 of them a single line. The end of your line was a wall you
could not see.

The span crosses runs now. It takes the rest of the run it starts in,
everything between that and the far end in reading order, and the far end's
own run up to the word you picked — what a drag down the page would have
taken. Every piece of it is highlighted, so what lights up is exactly what
⌘C gives you. A diff, a chat log, a page of prose: the far end is wherever
your eyes are. And because the whole screen is searched again the moment you
anchor, the chips now gather around your anchor rather than at the top of
the page.

One word no longer costs two picks either. ⇧letter lands on the whole word,
lit — and ⌘C there takes it and ends the mode: copied, still highlighted,
the next verb yours, the same ending a finished span has always reached. The
second anchor is what a span needs, not what a word needs. Type, pick, ⌘C.
Use the other command key for it: your lode key is a command key itself, so
lode C still exits select and runs the graph's C.

One thing to know before you lean on it. Select reads the whole visible
screen, so a span between two words far apart takes everything visually
between them, other windows included. Between two lines of the same page —
which is what this is for — it takes the page.
