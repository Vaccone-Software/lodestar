The walkthrough could lock a keyboard on a new install. It cannot now.

Every key reached it through the engine's event tap, and the tap needs the
Accessibility grant the first card is asking for. So on a machine that had not
granted it yet, nothing arrived: not return, not escape. A full screen panel
with no way out, while the macOS prompt and the settings pane opened behind the
backdrop where they could not be used or even seen.

The walkthrough now takes keys itself, through AppKit, which does not need any
permission at all. The tap is still first when it is running, and it swallows
each key before AppKit is offered it, so nothing is handled twice. When there
is no tap the panel is the floor. Verified with the tap absent: return pages
the deck, escape leaves.

Asking for the permission clears the screen. The card takes every window of
ours off the display, raises the macOS prompt, and waits, so the prompt and the
pane behind it are unobstructed. When the grant lands the walkthrough comes
back on its own, and the settings window closes with it if it was opened for
this and not something you were already working in.

The card also comes back when the answer is not yet: if the pane is closed
without granting, or the prompt is dismissed without ever opening it. Nothing
of ours swallows a key while it is off the screen, since the grant can land at
any moment and start the tap.

Accessibility has a button, because the one card that asks for the permission
is the one card that cannot assume a keyboard is reaching it. It reads Grant
Access until macOS has spent its single prompt, and Open System Settings after
that. The footer says esc to leave, on the card where that mattered most and
was not said.

Boot no longer fires its own prompt when the walkthrough is up. Two prompts for
one permission, one of them behind a backdrop, was most of what made this
unrecoverable.
