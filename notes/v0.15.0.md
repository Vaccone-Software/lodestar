Text becomes an address: select arrives on `lode /`.

The mouse's last stronghold was text. You could reach any window without
it, and then you dragged to select three words. Now the text itself is
the address: press `lode /`, type a few characters of anything you can
see, and every match on screen lights up wearing a capital chip. A
shifted letter anchors the start; type again, pick again, and the span
between the two anchors is selected. Lowercase always searches, capitals
always pick, and shift is a door rather than a hold: only the first
letter of a chip needs it. The span snaps to word boundaries, so two
typed characters name a word without dissecting it, and a URL or an
identifier comes out whole. There is no direction to get wrong: the span
is whatever lies between your two anchors.

The sensor is the screen itself. Lodestar captures the active display
and reads it with the system's recognizer, so select behaves identically
in a terminal, a browser, a chat history, or anything else with visible
text, focused or not. The first use asks for the Screen Recording
permission (grant it, then quit and reopen Lodestar); until then an
accessibility fallback covers what it can. Recognition runs twice over
one frozen frame, fast to appear and accurate to be right.

The mode always ends the same way: the span is highlighted and the next
verb is yours. In the field you are editing it becomes a real selection,
so copy, replace, and delete work from muscle memory. Everywhere else
Lodestar holds the highlight itself: `⌘C` copies it into the clipboard
history, anything else dismisses it. Copied text is checked against what
accessibility could read of the same region, so a recognized `1` that
was really an `l` comes out corrected — what you paste is what was
there, not what the pixels resembled.

Select also joins the observations: how often it completes, where it
gets abandoned, what it costs in keys and seconds — counts, never
content — so the coach can reason about it like everything else.
