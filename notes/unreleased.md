Your saved addresses and settings are now encrypted on disk too, and uninstalling with --purge removes the keys as well as the data.

Lodestar's state file (your breaths with their window titles and URLs, the windows it has parked, how often you use each app, and how far the walk has got) is now sealed at rest under a key in your login keychain, like the clipboard history and the health record. What is already on disk is encrypted at the first launch, checked, and only then is the plain copy removed. If the keychain cannot be opened, Lodestar runs without your saved addresses for that launch, never writes them in the clear, and loads them when the keychain answers, keeping what you changed in the meantime. If the key is gone, the unreadable file is moved aside, never deleted, and you are told. `lodestar diagnose` now says whether the state is sealed and opens.

`lodestar uninstall --purge` now also deletes Lodestar's keys from your login keychain, after the data they opened. `--dry-run` lists the step, a plain uninstall keeps the keys because the data it keeps cannot be read without them, and a key the keychain would not delete is named instead of passed over.

The config file now has one description, and everything about it comes from that: the defaults, what each option accepts, the words that explain it, the schema your editor reads, the old spellings it still understands, and the order a save writes. `lodestar.json` and `lodestar-schema.json` keep their names and their place, and a file written by an earlier version is written back byte for byte.

Problems with your config are clearer and come in the order of the file. Each one names the option as you would type it in `lodestar config get`, says what is wrong, and offers the nearest right answer, for a value as well as a key: `lode.trigger: "right-comand" is not allowed, expected one of "right-command", "left-command" (did you mean 'right-command'?)`. A misspelt gesture name is caught the same way. A number out of range says what it became (`scroll.speed: 99999 is out of range, expected a number between 200 and 4000; clamped to 4000`), and the next save writes the number it became. One bad entry in a table, a route or an app you never record clips from, is dropped with a message that names it, and the entries beside it still apply. `lodestar check --json` still gives one string per problem.

A few things that used to be forgiven are now said. A decimal where a whole number belongs (`lead-minutes`, a size in megabytes) is a problem and the default stands, where it was quietly cut. A model or language has to be spelled as listed (`"Full"` was read as `full`, with a complaint, and is now read as the default, with the same complaint). A `null` for a section or table is still read as nothing. In a file with keys Lodestar does not know, those keys now follow the known ones when it saves.
