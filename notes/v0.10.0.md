Lodestar can be your default browser, and links you click follow the
same rules links you type already followed.

Routes have always been able to say that anything matching x.com opens
in your personal profile. Until now they only applied when you asked
Lodestar, in the web bar, which is the half of the problem that needs
them least: typing a destination is exactly the moment you had the
chance to choose. Clicking a link in Notes or Slack is the moment you
had none, and that is where the profile is wrong often enough to be a
habit. Set Lodestar as your default browser and the table applies there
too.

The premise is that nothing changes. A link matching no rule goes to
your browser, untouched, brought forward the way a click always brought
it, and Lodestar does not rewrite the URL, place the window, or pull it
into your layout. Doing nothing is the behavior rather than a fallback
bolted onto something clever, so the common path is the empty one and a
link cannot be lost by code that does not run. Only a matched rule
diverts, and only then is a profile launch paid for.

Turning it on is one choice in System Settings, under Desktop and Dock.
The menu bar item takes you there. Lodestar quietly remembers which
browser answered for links before it did, so unrouted links have
somewhere to go that is not a guess. The first attempt did guess, by
asking the system what else could open a link, and it was wrong in the
way that matters: the answer reshuffles the moment Lodestar takes the
role, so the browser you were using drops out of first place and
Apple's own rises. Remembering costs one question at startup and is
never wrong.

Standing down is the same item again. Routing stops immediately and
every link goes straight through, whether or not macOS lets the role go
back in the same breath. Setting web.clicks.enabled to false does the
same from the config file, without a trip through System Settings:
Lodestar stays registered and becomes a pass-through. That is the off
switch worth having, because it works when nothing else is behaving.

Nothing about where you go is written down. Not a URL, not a host, not
a query, and the trace that can log a host is off by default. A config
edit records the name you chose and never the destination.

One more piece of housekeeping, invisible until it saves you. Lodestar
updates itself in the background, and a window manager that fails to
place a window is obvious, while a build that fails to route a link is
not: it fails silently, in other applications, on a machine where every
link now depends on it. So while Lodestar holds the browser role, the
update watchdog stops accepting "it booted" as proof. The successor has
to answer a routing question in its own voice, or it gets rolled back.
